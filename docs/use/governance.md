# Assemblies and decisions

The manager runs an assembly of owners from start to finish in the system. The rules below are the defaults of the Turkish pack (Law 634); a site without a pack uses generic defaults and can set every value by hand. See [Turkish pack](../packs/tr.md) for the legal status of each value.

## The assembly

1. **Call** with the agenda and the second-meeting date, produced as a letter. Delivery is tracked **per owner** (registered-mail number, signed by hand, or e-mail or SMS if the management plan allows), because that record matters if a decision is challenged.
2. **Agenda items**, each marked as voted or not.
3. **Pre-meeting polls.** Owners can answer **non-binding** polls from the app so the manager sees the mood. The binding vote happens in the room and the manager records the counts.
4. **Attendance** on the day: the manager ticks owners off on a screen (present, or represented by whom), and owners can check in by QR code from the app or printed on the call letter. Both mark the same record.
5. **Live quorum check** under the site's rules.
6. **Decisions** per agenda item with vote counts, outcome and dissent notes.
7. **Minutes** as a PDF, filed into the site documents automatically.
8. A searchable decision history with sequence numbers, for copying into the physical notarized decision book.

## Decisions that change things

A recorded decision can create the change it describes (for example a new dues amount or a new board), with the manager confirming each one and the link kept for audit.

## Elections and terms

Manager, board and auditor memberships have start and end dates and are created from the electing decision. The system reminds the site before terms expire so the assembly can be called in time; a new election ends the old terms.

## Limits

Binding online voting is not built: it has no clear basis under the law. Board meetings and block-level assemblies come later; a multi-block site holds one site-wide assembly.
